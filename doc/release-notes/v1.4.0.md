# RCPU Core v1.4.0 Release Notes

> **Status:** released (tag `v1.4.0`). **MANDATORY upgrade before block
> 21,000 for every node, pool and miner that validates or mines Etchash
> blocks.** This release fixes the Etchash hash domain so that standard GPU
> miners can mine RCPU's second algorithm. RandomX block validation and all
> historical blocks are unchanged.

## Critical: Etchash header hash no longer includes the nonce

RCPU v1.3.10 and earlier computed the Etchash 32-byte header hash over the
**whole 112-byte header, nonce included**:

```text
header_hash = keccak256(version ‖ prevhash ‖ merkleroot ‖ time ‖ bits ‖ nNonce ‖ 0)
result      = hashimoto(header_hash, nonce)
```

Because `nNonce` sat inside the hashed header, `header_hash` changed for every
nonce. That is incompatible with standard Ethash/Etchash, where the miner keeps
`header_hash` constant and only varies the nonce (the nonce enters hashimoto's
40-byte seed, not the header hash). Every stock GPU kernel — ethminer, lolMiner,
T-Rex — therefore produced invalid results on RCPU.

v1.4.0 implements the standard domain:

```text
header_hash = keccak256(header with nNonce = 0, hashRandomX = 0)
result      = hashimoto(header_hash, nonce8 = nNonce ‖ 0x00000000)
```

The nonce still lives in the block header (it is part of the block identity and
is submitted normally); it is simply **excluded from the hashed header**.

### Why this is safe to change now

- No Etchash block exists on mainnet, testnet or regtest: activation height
  21,000 has not been reached.
- RandomX, ASERT, the bit-30 dispatch, the second-algo count cache and all
  historical blocks are untouched.
- After 21,000 this would be a hard fork; before it, it is a pre-activation
  rule change.

### Impact if you do not upgrade

- A v1.3.10-or-earlier node rejects Etchash blocks produced by v1.4.0 nodes
  (and vice versa): the network splits at the first bit-30 block at 21,000.
- Pools and miners using the old domain produce blocks rejected as `high-hash`.

### Mandatory companion versions

- **Node:** v1.4.0 or later.
- **Miner:** `rcpuminer` **1.0.26 or later** (standard Etchash header domain; 1.0.25 has an epoch-boundary race that crashes the miner, 1.0.24 and earlier use the old domain).
- **Pool:** the Miningcore RCPU plugin revision that zeroes the nonce before
  hashing the 112-byte header.

Do not mix versions across 21,000.

## Changed

- `src/pow.cpp`: `CheckProofOfWorkEtchash()` zeroes `nNonce` before serializing
  the header and hashing it; the nonce is passed to `HashimotoLight()`
  separately.
- `src/test/dualalgo_tests.cpp`: new regression
  `etchash_header_hash_is_nonce_independent` — it recomputes the result in the
  standard domain and asserts it matches, and that the old domain does **not**
  match (so the test cannot pass with the old rule).
- Documentation: `doc/consensus-params.md`.

## Not changed

- RandomX header domain, commitment and epoch rules.
- Etchash epoch length (6000), seed derivation, DAG/cache sizes.
- Big-endian result comparison (v1.3.7 rule) — unchanged.
- ASERT difficulty, dual-algo dispatch, block/transaction/CT/wallet formats.

## Verification

- Unit: `dualalgo_tests` (including the new nonce-independence test) and
  `pow_tests` pass.
- Functional: private `rcpuregtest` chain — 44 Etchash blocks mined by an
  external miner through a pool and accepted by a v1.4.0 node; blocks carry
  `version=0x…` bit 30 and are validated in the new domain.
- Negative control: submitting a block built with the old domain is rejected
  with `high-hash` / `Possible spam. etchash value in block [...] != computed`.

## Upgrade

1. Stop node, pool and miner.
2. Upgrade all three (node v1.4.0, pool plugin revision, miner 1.0.26).
3. Restart the node, then the pool.
4. Miners reconnect with the new binary.
