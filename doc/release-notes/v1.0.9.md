# RCPU Core version v1.0.9

RCPU Core v1.0.9 是共识加固版本，关闭"机密 coinbase 输出"漏洞。

## 升级说明（重要）

- **旧包（v1.0.8 及更早）仍会接受机密 coinbase 输出，必须升级到本版本。**
- 本版本只需替换二进制，不需要重新同步或 reindex；历史区块全部符合新规则（见下），主网无需重组。
- 此漏洞此前未在主网触发：主网历史 0–4588 高度的 coinbase 输出全部为显式（explicit）值。但旧包在规则层面并未拒绝机密 coinbase，属于"恰好干净、不是规则已关"的未完成共识事故，故本次收紧向后兼容、无 soft-fork 风险。

## 共识规则变更

- 新规则（`CheckCoinbaseOutputsExplicit`）强制要求：**每个区块中的 coinbase（第一笔交易）的所有输出必须是显式金额（`IsExplicit()`）**；任何输出为机密（confidential）金额即拒绝该区块，错误码 `bad-cb-confidential`。
- 规则在两条路径强制执行：
  - 路径 A：`CheckBlock` 中立即校验（区块头级独立检查，最早拒绝）；
  - 路径 B：`ConnectBlock` 中在 `blockReward` 计算完成、`GetValueOut() > blockReward` 补贴过剩比较之前校验，失败即整块回滚（双重保险，覆盖所有连接路径）。
- 普通交易输出的机密金额（CT）不受影响；本次只封死铸币侧的漏洞。

## 验证

- 回归测试：`src/test/coinbase_confidential_tests`（6 用例 / 19 断言），使用主网真实区块 hex 回放三种场景：
  - A（全显式 coinbase，h=4）→ 通过；
  - B（全机密 coinbase，h=2）→ 拒绝 `bad-cb-confidential`；
  - C（显式 2000 + 机密混合 coinbase，h=3）→ 拒绝 `bad-cb-confidential`。
- 发布流水线新增共识门禁：对产物二进制执行 `strings rcpud | grep bad-cb-confidential` 与 `CheckCoinbaseOutputsExplicit` 符号检查，未通过不发布。

## 版本对齐

- 版本字符串统一为 `1.0.9`。已清除历史遗留的 `narnia` / `1.0.2` / `1.0.8` 混用，版本号与真实规则集一致。
