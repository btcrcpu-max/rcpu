# RCPU Core v1.4.1 Release Notes

> **Status:** released (tag `v1.4.1`). This release contains a consensus
> tightening for confidential transactions plus RPC and accounting fixes. Any
> node, pool, explorer, indexer or miner that parses RCPU transactions or UTXO
> statistics should read "Compatibility" before upgrading.

## Consensus: a confidential transaction input must not carry a value

The confidential-transaction wire format serializes a per-input `CTxIn::nValue`
for `nVersion == 3`, but no consensus rule read it and no signature hash covered
it: the legacy `SerializeInput`, BIP143 and BIP341 all omit it. A third party
could therefore rewrite the field on a broadcast transaction, keeping every
signature valid while changing the txid.

v1.4.1 rejects any v3 transaction whose `CTxIn::nValue` is not null
(`bad-txns-ct-input-value`). No wallet code path ever set the field, and a
full-chain scan of mainnet blocks 0..20364 (35,423 v3 inputs) found zero
non-null values, so this is a tightening rule: no historical block is affected
and no reindex is required.

## RPC: confidential values are reported as unknown, never as 0

`CTxOut::nValue.GetAmount()` returns 0 for a Pedersen commitment, and several
RPCs reported that 0 as if the output were worth nothing.

- **`decodepsbt`**: `witness_utxo` reports `"confidential": true` and omits
  `amount`. `fee` is omitted when any input or output is confidential;
  `analyzepsbt` likewise omits `fee` and `estimated_feerate`, but still reports
  `estimated_vsize`.
- **`gettxoutsetinfo`**: adds `amounts_complete` and, when known,
  `confidential_outputs`. `total_amount` keeps its previous meaning, which on a
  confidential-transactions chain is the **explicit part only**;
  `amounts_complete: false` says exactly that. Measured on mainnet before this
  release, `total_amount` was 80.82% of issuance, i.e. 19.18% of the supply was
  invisible to the metric.
- **`scantxoutset`**: the per-output `amount` is omitted for a commitment and
  replaced by `"confidential": true`; adds `amounts_complete` and
  `confidential_outputs` at the top level.
- **`gettxout`**: reports `confidential: true` and omits `value` for a
  commitment.
- **`getblockstats`**: adds `amounts_complete`; `utxo_size_inc` now serializes
  outputs with the transaction's own mode (previously a confidential output was
  measured as a plain 8-byte amount, undercounting by about 2.6 kB each).

## Wallet: `fundrawtransaction` rejects confidential outputs

`fundrawtransaction` used 0 as the amount of a confidential output, which
silently understated the output total and could lead to the wrong coins or
change being selected. It now fails with `RPC_INVALID_PARAMETER` instead. Build
the transaction with explicit amounts and let the wallet blind the outputs
itself.

## Upgrade notes

- **Rebuild the coinstatsindex** if you run with `-coinstatsindex`. The old index
  counted fee outputs (an explicit value with an empty scriptPubKey) in its
  totals and in its muhash, although those outputs never enter the UTXO set, so
  its numbers disagreed with the non-index `gettxoutsetinfo` path. Such an index
  is now refused at startup: delete the index directory (or start with
  `-reindex`) and let it rebuild. No other index, the chainstate or the wallet
  are affected.
- No reindex is needed for the consensus rule or for the other RPC changes.

## Compatibility

- Tools that assumed "confidential output => amount 0" must be updated: the
  amount field is now absent and a `confidential` flag is set instead.
- Tools that read `gettxoutsetinfo.total_amount` as the whole supply should
  check `amounts_complete` first.

## Internal

- Removed the unused `CT_FORK_HEIGHT` constant. The CT activation height is
  `Consensus::Params::nCTActivationHeight`, which is 0 (active from genesis) on
  every RCPU network.
