# RCPU Core v1.3.3 Release Notes

> **Status:** released (tag `v1.3.3`). **All nodes and pools must upgrade
> before height 21,000.** This release fixes a network-layer regression in the
> Etchash pre-activation checks; it does not change consensus rules for valid
> blocks.

## Fixed: Etchash headers were rejected as invalid PoW after activation

v1.3.0–v1.3.2 switched the bit-30 algorithm to **Etchash**
(`fDualAlgoEtchash = true`) but two height-unaware PoW pre-checks still probed
only qhash + RandomX:

- `HasValidProofOfWork()` — the network-layer headers pre-check
  (`CheckHeadersPoW`) — is run on every `headers` message. Every relayed
  Etchash header failed both probes and the sending peer was charged **100
  misbehaviour points** (`header with invalid proof of work`), i.e. it was
  discouraged and disconnected. Since roughly half of post-activation blocks
  are Etchash, headers sync and BIP130/CMPCT block announcement would break
  right after height 21,000.
- `CheckBlock(..., nHeight = -1)` — the context-free block check used when the
  parent is not yet known — rejected a valid Etchash block as `high-hash`
  before `AcceptBlockHeader` could re-verify it with the real height.

### Fix

- `HasValidProofOfWork(headers, params, nStartHeight)` now verifies bit-30
  headers with `CheckProofOfWorkEtchash(header, height, ...)` using the height
  derived from the batch start; when the height is unknown the PoW verdict is
  deferred to `AcceptBlockHeader`, which always runs with `pindexPrev`.
- `CheckHeadersPoW()` passes `chain_start->nHeight + 1` and checks header
  continuity before the PoW pass, so per-header heights are meaningful (a
  non-continuous batch is still rejected, with 20 points instead of 100).
- `CheckBlock()` no longer runs the qhash/RandomX probe for bit-30 blocks on
  Etchash chains when the height is unknown.
- Regression tests: `dualalgo_tests` covers a valid Etchash header passing the
  pre-check, a tampered one failing, unknown-height deferral, and
  `CheckBlock(..., nHeight = -1)`. `dualalgo_tests` is now part of the CI
  suite whitelist and the fail-closed suite assertion.

## Upgrade requirement

- **Nodes, pools and miners must upgrade before height 21,000.** Old binaries
  will disconnect peers that relay Etchash headers and can stall header sync.
- No consensus change for valid blocks: verification results for blocks and
  headers are unchanged; only the false-negative pre-checks are fixed.
- Asset names are generated from `PACKAGE_VERSION` and match the tag
  (`rcpu-1.3.3-*`).

## Verification

- CI (build, make-check with `dualalgo_tests`, GUI build, functional tests) and
  docker-smoke are green on the merged commit.
- The pre-activation fix was reviewed and merged as PR #90 (squash commit
  `fix(pow): verify Etchash in height-aware PoW pre-checks`).
