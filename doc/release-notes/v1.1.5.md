RCPU Core v1.1.5 Release Notes
================================

## CT Send Path Fix (#51)

`src/wallet/spend.cpp` and `src/blind.cpp` were hardened so confidential
transaction sending is **fail-closed** instead of degrading silently:

- **rcpux1 recipients**: the blinding key is resolved from the destination;
  sending is refused when the confidential public key is missing (no
  Path-A fallback), instead of producing an invalid transaction.
- **Bare rcpux2/rcpu1 recipients**: explicit plaintext output (no `0x02`
  nonce) is created.
- **Change output**: stays Path B (blinded `0x03`).
- **Explicit outputs**: skip blinding like fees via `ExplicitCommit`
  (tally-safe).
- `BlindTransaction` returns `false` when all outputs are
  explicit/fee but non-zero input blinds are present, preventing
  `bad-txns-ct-balance`.
- An all-plaintext transaction falls back to legacy v2 to avoid an
  all-explicit v3 layout.
- A CT input without any confidential output is refused in
  `CreateTransaction`.
- Recipients are matched by destination slot instead of first-matching
  script.
