# RCPU Core v1.4.4 Release Notes

> **Status:** unreleased. No consensus changes.

## Wallet: legacy change outputs are no longer unspendable under confidential transactions

With confidential transactions enabled (the default on every RCPU network),
the wallet rewrote a legacy (P2PKH) change destination to its confidential
form so the change output could be blinded. That rewrite also changes the
output script from `pkh(key)` to `wpkh(key)`. A descriptor wallet's legacy
spend manager derives only `pkh(key)`, so the rewritten change was not
recognised as owned by the wallet: it was missing from `listunspent` /
`getbalance` and could never be spent.

The wallet now adopts the confidential form only when it actually owns the
resulting `wpkh(key)` script. Otherwise the change remains an explicit P2PKH
output. This is valid because the path is only taken when the wallet holds no
blinded UTXO, so the spend has explicit inputs and uses the all-explicit v2
serialization.

Affected: descriptor wallets paying a legacy (P2PKH) address, and wallets
started with `-addresstype=legacy`, when their available coins are explicit.
Change already sent to such a `wpkh(key)` output is not recoverable by the
wallet unless the key was imported into another wallet.

## Tests

`wallet_tests` is now part of the scoped unit-test gate (thirteen suites),
covering the regression above.
