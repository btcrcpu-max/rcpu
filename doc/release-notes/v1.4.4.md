# RCPU Core v1.4.4 Release Notes

> **Status:** v1.4.4. No consensus changes.

## GUI wallet security hardening

- **New wallets are encrypted by default.** The Create Wallet dialog now selects
  "Encrypt Wallet" and requires a passphrase. Users can still opt out by
  unchecking the box, but the default no longer produces a plaintext
  `wallet.dat`.
- **Wallet KDF raised to 1,000,000 rounds** for new encryption and passphrase
  changes (previously 25,000). Existing wallets keep the iteration count stored
  in their own `CMasterKey` and continue to unlock normally. Expect roughly
  0.3–0.5 seconds extra for create/unlock on a modern desktop.
- **Minimum passphrase length is 10 characters** for new encryption and
  passphrase changes. The OK button stays disabled until both fields meet the
  minimum. Existing passphrases are unaffected.
- **Idle auto-lock:** encrypted wallets are locked after 10 minutes without
  mouse/keyboard/wheel activity. A new **Settings → Lock Wallet Now** action
  locks immediately. The timeout can be changed with the QSettings key
  `walletLockTimeoutMin` (minutes; `0` disables it).
- **Unencrypted wallets are now visible:** the status-bar lock icon is shown
  with a warning tooltip instead of being hidden.
- **Example RPC config binds to localhost explicitly:**
  `share/examples/rcpu.conf` now ships `rpcbind=127.0.0.1` and
  `rpcallowip=127.0.0.1`. Do not change these to `0.0.0.0`; use an SSH tunnel
  or WireGuard for remote access.

## Upgrade notes

- Existing encrypted wallets are **not** re-encrypted automatically. To move an
  old wallet to the new KDF, use **Settings → Change Passphrase** (this
  re-encrypts the master key with the new default).
- If you forget the passphrase, the funds cannot be recovered. Back up the
  passphrase separately from `wallet.dat`.
- After enabling encryption, destroy any old **unencrypted** `wallet.dat`
  backups (local, cloud, USB, old PCs): they still contain plaintext keys.
- Windows binaries are **not Authenticode-signed**. Verify the release with
  `SHA256SUMS` and the detached GPG signature before installing.

## Tests

- CI: `build`, `build-gui` (Qt5 compile + linkage), `make-check` unit suites,
  `functional tests` (CT wallet), `docker-smoke`, `source build + regtest smoke`,
  and release template checks all pass.
- `wallet_crypto_tests` use explicit 25,000-round vectors and are unaffected by
  the new default.
