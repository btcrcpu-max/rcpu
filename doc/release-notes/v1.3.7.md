# RCPU Core v1.3.7 Release Notes

> **Status:** released (tag `v1.3.7`). **MANDATORY upgrade before block 21,000
> for every node, pool and miner that validates or mines Etchash blocks.**
> This release publishes the Etchash big-endian result rule that was committed
> after v1.3.6. RandomX block validation and all historical blocks are
> unchanged.

## Critical: Etchash result comparison is big-endian from block 21,000

RCPU v1.3.6 and earlier interpreted the 32-byte `hashimotoLight` result as a
**little-endian** 256-bit number. Standard Etchash (geth / core-geth /
ethminer) treats the same bytes as a **big-endian** number:

```text
result = keccak256(seed64 || digest)
valid  <=>  BE(result) <= target      (v1.3.7+, from height 21,000)
```

v1.3.7 implements the standard comparison from `nEtchashBigEndianHeight`
(mainnet/testnet: 21,000; regtest: 0). Because Etchash does not exist before
21,000, the first Etchash block on every RCPU chain uses the big-endian rule.

### Impact if you do not upgrade

- A v1.3.6-or-earlier node rejects Etchash blocks produced by v1.3.7 nodes
  (and vice versa): the network splits at the first bit-30 block at/after
  21,000.
- An upgraded node can refuse to start if its block index already contains an
  Etchash block accepted under the old little-endian rule. If that has
  happened on your node or on testnet, reindex the chain after upgrading.
- Pools and miners that still use the old little-endian comparison will keep
  producing shares that the upgraded node rejects as `high-hash`.

### Mandatory companion versions

- **Node:** v1.3.7 or later.
- **Miner:** `rcpuminer` 1.0.23 or later (big-endian target comparison and
  dataset-size light cache).
- **Pool:** the Miningcore RCPU plugin revision that compares Etchash targets
  big-endian and reads `etchash_seed_hash` as raw bytes (not reversed).

Do not mix versions across 21,000.

## What changed

- `src/pow.cpp`: `CheckProofOfWorkEtchash()` compares the hashimoto result as
  a big-endian number at/after `nEtchashBigEndianHeight`.
- `src/node/blockstorage.cpp`: the startup block-index sanity check applies the
  same big-endian rule, so disk state and consensus cannot disagree.
- `src/rpc/mining.cpp`: `getblocktemplate` returns `etchash_seed_hash` in raw
  byte order (not `uint256::GetHex()`-reversed).
- New unit and functional regressions for the big-endian path (see
  `src/test/dualalgo_tests.cpp` and `test/functional/`).
- Documentation: `doc/consensus-params.md`, `doc/randomx-mining.md`,
  `doc/release-notes.md`, `README.md`.

## Upgrade instructions

1. Stop the node, pool and miner.
2. Back up `wallet.dat` and the node data directory.
3. Install v1.3.7 (node) and the matching miner/pool versions.
4. Start the node and verify the tip:

   ```bash
   rcpu-cli getblockcount
   rcpu-cli getblockchaininfo
   ```

5. If the node fails during block-index load with a PoW error and you know it
   previously followed a little-endian Etchash chain (typically a testnet),
   reindex:

   ```bash
   rcpud -reindex
   ```

6. Start the pool/miner only after the node is fully synced and reports the
   expected tip.

## Compatibility

- RandomX blocks, CT transactions, wallet formats and all historical blocks
  are unchanged.
- Mainnet/testnet activation height remains 21,000; regtest remains 150 for
  dual-algo and 0 for the big-endian gate.
- Asset names: `rcpu-1.3.7-*`.

## Verification

- `dualalgo_tests`: big-endian result ordering, big-endian PoW round-trip, and
  the height-gated legacy path.
- Functional tests: `feature_dualalgo_count_cache.py` (regtest activation and
  count-cache rebuild) and the RCPU CT wallet suites.
- Release binaries are built from the `v1.3.7` tag by the `Release Full
  (Linux + Windows)` and `Release GUI (AppImage)` workflows.
