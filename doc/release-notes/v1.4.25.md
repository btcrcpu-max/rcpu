# RCPU Core v1.4.25 release notes

v1.4.25 is a hardening release: it adds startup validation for the dual-algo
consensus parameters, keeps the RCPU header layout tied to the selected chain,
and repairs the unit-test suite. **No consensus change, no wallet migration, no
RPC behaviour change**, and no change to any difficulty or block-acceptance
rule.

## Node startup validation

`GetDualAlgoWorkRequired()` divides by `nASERTHalfLife` / `nDualAlgoTargetSpacing`
and falls back to `powLimit` when `GetAncestor(nActHeight - 1)` finds nothing. The
`assert` guarding the latter is compiled out of release builds, so a chain
configured with `nDualAlgoActivationHeight = 0` (or a zero half-life) would have
silently accepted minimum-difficulty blocks.

`Consensus::Params::CheckDualAlgoConsistency()` now runs from
`CreateChainParams()` for every chain type and refuses such a schedule at
startup. It is a startup check only: no computed target changes, and the
shipped chains (mainnet, testnet, regtest) pass it.

## Header layout follows the selected chain

`g_isRandomX` decides whether `CBlockHeader` serialises the 112-byte RCPU layout
(with `hashRandomX`) or the legacy 80-byte one. Only `AppInitMain` and
`rcpu-chainstate` used to set it, so any entry point that just called
`SelectParams()` - tools and tests - wrote 80-byte headers while the chain still
verified RandomX, and a block read back from disk came out with
`hashRandomX == null` ("missing commitment field").

Each chain's parameter constructor now sets the flag before hashing its genesis,
and `SelectParams()` sets it from the selected chain. This is the value the node
already used; binaries behave the same, non-node entry points now agree with
them.

## Test suite and CI

- the CI unit-test gate grew from 12 to 17 suites (`argsman_tests`,
  `validation_block_tests`, `descriptor_tests`, `txvalidationcache_tests`,
  `ismine_tests`, `wallet_tests`), and the step now fails closed if a suite was
  not actually entered;
- the `--run_test` list used to be narrowed to a single suite by a `:` in the
  filter, so most of the gate never ran - fixed;
- `validation_block_tests` mined with SHA256d and crashed the whole binary; it
  now uses the RCPU PoW, and the suite is part of the gate;
- fixtures that decode historical Bitcoin blocks do so with the layout those
  blocks were captured under;
- `assumeutxo` cases skip on chains that ship no snapshot data;
- six suites that assert on Bitcoin block hashes (`bloom_tests`,
  `merkleblock_tests`, `blockfilter_tests`, `blockfilter_index_tests`,
  `blockencodings_tests`, `blockmanager_tests`) are disabled: RCPU hashes a
  112-byte header, so those vectors cannot exist on this chain.

## Compatibility

- Consensus: unchanged. No reindex required.
- Wallet: no migration.
- RPC: unchanged.
- Node: the binary differs from v1.4.24 only in the startup validation and the
  header-layout bookkeeping described above.
