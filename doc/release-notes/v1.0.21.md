# RCPU Core v1.0.21 Release Notes

This release adds **confidential addresses** (`rcpux1...`) and the Path-A /
Path-B wallet sending split.

## Confidential addresses (`rcpux1...`)

- Encoding, decoding and validation of `rcpux1...` confidential addresses in
  `src/key_io.cpp` (mainnet prefix `rcpux1`, regtest `rrcpux1`).
- Wallet send/receive/change and GUI support for confidential addresses.
- `createTransaction` now exposes the original confidential address as
  `vout_addr`, so history/UI can show the human-readable address.

## Path-A / Path-B sending

- Path A (legacy nonce `0x02`, anyone can rewind) is used only for
  legacy / no-public-key outputs.
- Path B (ECDH with the recipient spend pubkey, `0x03`-prefixed ephemeral
  key) is used for `ConfidentialKeyHash` recipient keys; only the recipient
  can unblind.
- The blinding loop no longer falls back to `ExtractDestination` when
  recipient keys are unavailable.

## Validation

- The RandomX commitment check is now epoch-independent and runs in the
  context-free `CheckBlock`, so it no longer depends on the current epoch.

## Display

- Path-B CT outputs show their plaintext amount via the `vout_amount`
  fallback in wallet display instead of an unmapped commitment.
