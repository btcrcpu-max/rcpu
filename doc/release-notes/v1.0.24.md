# RCPU Core v1.0.24 Release Notes

## Windows wallet sync fix (RandomX native build)

RCPU GUI wallets released on Windows (v1.0.21/v1.0.23) could not synchronize
past the built-in checkpoint heights 2000/4000 and stayed stuck with
`high-hash, proof of work failed` on blocks validated fine by Linux nodes.

**Root cause:** the official Windows binaries were built by cross-compiling
the RandomX library on Ubuntu 22.04 (`g++-mingw-w64-x86-64-posix`, GCC 12).
That cross-compiled RandomX produced a different PoW hash for the same block
header than chain-accepted nodes (native Linux, native MSYS2/MinGW-w64),
causing the wallet's PoW verification to reject valid blocks.

**Fix:** the release workflow now builds RandomX natively on a Windows runner
with MSYS2/MinGW-w64 (GCC 16), which produces hashes byte-for-byte identical
to chain consensus. A **parity gate** step in CI recomputes the RandomX hash
of block A4000 (a chain-accepted block) and fails the build unless it matches —
so any future toolchain drift is caught before a release is published.

**Effect for users:** after upgrading to v1.0.24, Windows GUI wallets
synchronize to the latest height without manual checkpoint bypass or config
edits. Existing wallets and data directories are compatible; no reindex beyond
a normal re-sync is required.
