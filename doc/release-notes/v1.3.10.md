# RCPU Core v1.3.10 Release Notes

> **Status:** released (tag `v1.3.10`). This is a **P2P synchronization fix**,
> not a consensus change. Every block-validity and difficulty rule is identical
> to v1.3.8 and v1.3.9.

## Fixed: IBD / large headers catch-up could be disconnected by the 10x Etchash header budget

v1.3.9 charges each Etchash header **10 units** in the per-peer header budget
(20,000 burst, 2,000 units/s refill). A maximum-size batch is 2,000 headers, so
one full batch costs **20,000 units** and consumes the entire burst. The node
then spends about 5 seconds verifying the batch, during which the bucket only
refills ~10,000; the next full batch cannot be charged, the peer receives 20
misbehaviour points, and the batch is dropped. Repeated batches can disconnect
an honest node that is catching up after 21,000.

v1.3.10:

- While the node is in **initial block download**, every header is charged at
  **1x**, including Etchash headers. A 2,000-header batch costs 2,000, not
  20,000, so honest catch-up is not throttled by the 10x weight.
- If the budget is nevertheless exhausted during IBD, the batch is dropped
  **without** `Misbehaving()`; an honest peer is not punished for a large
  catch-up.
- Outside IBD, the 10x Etchash weight and the existing misbehaviour behaviour
  are unchanged. The known/ancestor header early-out from v1.3.8 is also
  unchanged.

## Boundary (deliberate)

`ChainstateManager::IsInitialBlockDownload()` latches `m_cached_finished_ibd`
once the node has left IBD. This fix therefore covers:

- a new node syncing from genesis;
- a node restarted after being offline longer than `max_tip_age` (default 24h);
- block loading / reindex.

It does **not** cover a process that has already finished IBD, stays running,
and later falls far behind without restarting (for example a very long network
partition). In that case the 10x weight still applies. If such a case is
observed, a follow-up can add a non-latching `far_behind` check; it is not
included here to keep this patch minimal.

## No consensus change

- No change to `pow.cpp`, `chainparams.cpp`, `CheckProofOfWorkEtchash()`,
  activation height 21,000, epoch, difficulty, or the big-endian rule.
- v1.3.8, v1.3.9 and v1.3.10 nodes accept the same blocks and targets.
- No coordinated upgrade window is required.

## Upgrade

- **Recommended** for any node that may sync or catch up after 21,000; it
  removes the v1.3.9 IBD regression.
- **Consensus baseline remains v1.3.7**: nodes/pools/miners validating bit-30
  blocks at/after 21,000 must run the big-endian rule. v1.3.10 carries it.
- Companion versions remain: miner **1.0.23+**, Miningcore pool with the
  big-endian target and raw `etchash_seed_hash` patch.
