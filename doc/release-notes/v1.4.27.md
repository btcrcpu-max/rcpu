# RCPU Core v1.4.27 release notes

v1.4.27 schedules the POW-02 never-mined resume rule that shipped inactive in
v1.4.18. It is a **consensus change with a fixed activation height**: every
node, pool and miner must upgrade before height **31,939**.

## Compatibility

- Mainnet and testnet activate POW-02 at height **31,939** (tip 29,923 on
  2026-11-24 + 2016 blocks; roughly 2026-12-01 at the ~5-minute cadence, earlier
  if the recent cadence holds).
- Before 31,939 the chain validates exactly as with v1.4.26. After it, a block
  from an algorithm that has **never** produced a block re-anchors to the
  activation anchor instead of staying at `powLimit`, so a chain whose second
  algorithm never starts can resume.
- No reindex is required. The rule only changes difficulty for new blocks; it
  does not change block or transaction formats.
- Nodes still on v1.4.26 or older stop following the chain after 31,939 if an
  algorithm is still missing. Upgrade before that height.
- The H-1 lateness cap (`nDualAlgoLatenessFixHeight = 29,909`) is unchanged and
  already active.

## Consensus

- **POW-02** `nDualAlgoNeverMinedFixHeight` is no longer `INT_MAX`:
  - mainnet: 31,939
  - testnet: 31,939 (same release, same height)
  - regtest: 0 (unchanged)
- New unit test `dual_algo_never_mined_is_scheduled_on_live_chains` pins the
  schedule so a silent revert fails CI.

## Notes

- Do not move the height once this release ships; schedule a new height in a
  later release instead.
- The 2026-11-24 replay of heights 20,999-29,923 against the live node matched
  both the pre-H-1 and H-1 columns with zero mismatches and zero re-anchors,
  confirming the fork activated cleanly.
