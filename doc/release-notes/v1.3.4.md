# RCPU Core v1.3.4 Release Notes

> **Status:** released (tag `v1.3.4`). **All nodes, pools and miners that intend
> to mine Etchash blocks must upgrade before height 21,000.** This release fixes
> a consensus-critical Etchash incompatibility; RandomX block validation is
> unchanged.

## Critical: Etchash `hashimotoLight` used the cache size instead of the DAG size

`HashimotoLight()` computed its row count as `cache_size / 128` (the ~16 MiB
epoch cache) instead of `dataset_size / 128` (the ~1 GiB full DAG). Standard
Ethash/Etchash implementations (go-ethereum, ethminer, and any independent
verifier) use the dataset size, so RCPU's Etchash digests/results differed from
standard Etchash from the first bit-30 block onward.

### Impact

- Nodes built from v1.3.3 or earlier reject Etchash blocks produced by standard
  miners/verifiers (and vice versa).
- The effective dataset row space was 64x smaller than designed, weakening the
  memory-hardness of the second algorithm.
- RCPU nodes among themselves were self-consistent, so no historical block or
  RandomX block is affected; no Etchash block exists yet (activation is at
  height 21,000).

### Fix

- Added `etchash::CalcDatasetSize(epoch)` (standard ethash: 1 GiB + 8 MiB per
  epoch, prime-bounded on `size / MIX_BYTES`).
- `HashimotoLight()` now takes the full-DAG size and uses
  `rows = dataset_size / 128`.
- `CheckProofOfWorkEtchash()` derives the DAG size from the epoch and passes it
  in; `getblocktemplate` now also reports `etchash_dataset_size` and
  `etchash_dataset_rows`.
- Tests now include the official go-ethereum `TestHashimoto` vector (1 KiB
  cache, 32 KiB dataset) plus the geth `datasetSizes` table, so a porting error
  cannot silently pass self-generated vectors.

## Upgrade requirement

- Every node, pool and miner that will mine or validate bit-30 blocks must run
  **v1.3.4 or later before the first Etchash block is mined** (activation height
  21,000, roughly a week after this release).
- Old nodes will reject the new Etchash blocks; new nodes reject the old
  (non-standard) ones. RandomX blocks remain compatible.
- If a miner cannot upgrade in time, it can keep mining RandomX-only blocks;
  bit-30 blocks are optional.

## Compatibility

- No change to RandomX, transaction/CT rules, or historical blocks.
- Asset names: `rcpu-1.3.4-*`.
