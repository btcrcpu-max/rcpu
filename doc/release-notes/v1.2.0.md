# RCPU Core v1.2.0 Release Notes

> **Status:** unreleased (in development on `feat/dual-algo-etchash`).
> Version string bumped to 1.2.0; tag not yet created on this branch.

## Dual-algo hard fork + Etchash light verification

- **Dual-algo at height 21,000** (mainnet/testnet; 150 regtest): blocks may
  be mined with RandomX or with the version-bit-30 algorithm. Each algorithm
  runs its own ASERT difficulty instance (600 s target spacing per algorithm,
  anchored at height 20,999 with reference target `nBits >> 1`).
- **`fDualAlgoEtchash = true`** on mainnet/testnet: bit-30 blocks are
  verified with **Etchash** (ECIP-1099-style **light** verification, no full
  DAG), epoch length **6000** blocks (epoch = `(height - 21000) / 6000`);
  10 blocks on regtest.
- **Legacy qhash (qPoW)** remains as fallback verifier when
  `fDualAlgoEtchash` is false (e.g. pre-etchash params / test vectors) and is
  marked deprecated on current params.
- `getblocktemplate` for bit-30 templates returns `algo="etchash"` with
  `etchash_epoch`, `etchash_epoch_length`, `etchash_seed_hash`,
  `etchash_cache_size`, `etchash_header_size`, `etchash_hash_field`,
  `etchash_commitment_target`, `etchash_pow_rule` — pools MUST use these and
  MUST NOT recompute epoch/seed from an assumed activation height.

## Consensus-critical notes

- Below height 21,000 the version bit 30 is ignored (RandomX-only rules,
  byte-identical to v1.1.x behavior).
- This is a consensus hard fork; all nodes and pools must upgrade before the
  activation height. See `doc/consensus-params.md` for the parameter table
  and `doc/randomx-mining.md` for pool/gbt integration details.
