# RCPU Core v1.4.28 release notes

v1.4.28 is a **non-consensus hardening release**. It follows the dual-algo
audit and fixes correctness/DoS issues in RandomX header verification, the
mining RPC and Etchash parameter handling. **No consensus rule changes, no
reindex, and no new mandatory activation height.**

The v1.4.27 POW-02 schedule remains in force: every node, pool and miner must
still upgrade to v1.4.27 or later before mainnet height **31,939**.

## RandomX header verification DoS (P2P)

The RandomX commitment-only header precheck is forgeable: the commitment is
`blake2b(header112, hashRandomX)`, and `hashRandomX` is an attacker-controlled
header field. Passing the commitment target does not prove RandomX work. The
real FULL verification runs in `AcceptBlockHeader()` while holding `cs_main`.

v1.4.28 adds a **process-wide budget for FULL RandomX header verification**:

- 2,000-header burst, 100 headers/s refill, shared by all peers;
- charged only after the commitment precheck passes, so invalid headers cannot
  starve honest peers;
- also charged for new `cmpctblock` headers;
- on exhaustion the batch is dropped without misbehavior; honest peers retry;
- P2P policy only: RPC, internal validation and mining are not throttled.

This caps the rate at which forged commitment headers can drive full RandomX
work under `cs_main`; it does not change consensus or block acceptance rules.

## Dual-algo correctness fixes

- **D-1/D-2**: corrected the misleading "RandomX commitment cannot be forged"
  comments. The commitment-only precheck is a cheap, forgeable filter; the FULL
  hash in `AcceptBlockHeader()` is the actual PoW check.
- **D-4**: `GenerateBlock()` now returns `false` when the nonce space is
  exhausted without a solution, instead of returning `true` with an empty
  `block_out` and letting `generateBlocks()` loop.
- **D-5**: `CheckDualAlgoConsistency()` now rejects `nEtchashEpochLength <= 0`.
  (The optional single-algo `asertAnchorParams` is intentionally not required;
  the dual-algo path anchors on the activation block / per-algorithm anchors.)
- **D-6**: `GenerateDatasetItem()` / `HashimotoLight()` now fail closed if the
  Etchash row count exceeds `uint32_t`, instead of silently truncating.
- **I-1**: `getblocktemplate` keeps the historical `rx_seed_hash` field and
  adds `rx_seed_hash_raw` (raw seed byte order) for external miners. The
  display-order caveat is documented in `doc/randomx-mining.md`.

## Compatibility

- No consensus change, no block/transaction format change, no reindex.
- v1.4.28 is a recommended upgrade for nodes exposed to inbound P2P; it is not
  a mandatory network upgrade.
- The v1.4.27 POW-02 activation at height 31,939 is unchanged and still
  mandatory for nodes that have not upgraded past v1.4.26.
- `rx_seed_hash` keeps its old byte order; miners that already parse it are
  unaffected. New miners should prefer `rx_seed_hash_raw`.

## Tests

- Full `test_bitcoin`: no errors.
- `dualalgo_tests`: no errors, including new epoch-length validation cases.
- `getblocktemplate` on rcpuregtest: `rx_seed_hash` / `rx_seed_hash_raw`
  verified as byte-reversed forms of the same seed; RPC self-check passes.
- CI: build, build-gui, make-check, functional tests, source build + regtest
  smoke, release template checks, docker.
