# RCPU Core version v1.0.15

Security release. No consensus change, no `-reindex` needed.

## Security

### M-2: skip `pedersen_blind_sum` when no CT outputs

`src/blind.cpp` previously called `pedersen_blind_sum` even when a transaction
had no confidential outputs (only fee outputs). An empty `blinds` vector
causes the secp256k1-zkp function to abort. The fix short-circuits this case
and returns `true` immediately, avoiding the fatal call.

Source: PR #18.

### M-3: skip fee outputs in `CalculateOutputValue`

`CalculateOutputValue` (used by wallet display and fee estimation) did not skip
`IsFee()` outputs, causing fee amounts to be counted toward the output total.
This was inconsistent with `GetValueOut`. The fix adds the same `IsFee()`
continue guard so fee outputs are excluded from the sum.

Source: PR #19.

### M-4: clamp ASERT on extreme time delta

`CalculateASERT` in `src/pow.cpp` could hit signed overflow when computing
`exponent = time_delta * 65536 / target_time` with very large time deltas,
or when `shifts` became extreme and `-shifts` wrapped around `INT64_MIN`.
The fix saturates `time_delta` before multiplication and clamps `shifts` to
`[-512, 512]`, returning `powLimit` or `1` respectively. Normal-block
difficulty is unchanged.

Source: PR #20.

### M-5: require strong RNG seed before continuing

The startup path never forced `m_strongly_seeded`; `RandomInit()` only
triggered `ProcRand(FAST)`, and `Random_SanityCheck` did not verify strong
seeding. This meant key material could be generated before `SeedStartup()`
had mixed OS entropy into the RNG state.

`RandomInit()` now walks the SLOW path and hard-fails via `RandFailure()`
if `IsStronglySeeded()` is false. `Random_SanityCheck()` falls back to
`GetStrongRandBytes()` and re-checks. `RandomInit()` is called before
`kernel::SanityChecks()` in `AppInitSanityChecks()`.

Source: PR #21.

After installing the new binaries, the network user agent becomes
`/RCPU:1.0.15/`. No reindex, no data directory migration required.
