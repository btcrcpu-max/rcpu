RCPU Core v1.0.25 Release Notes
================================

## Critical Bug Fix: Windows IBD High-Hash at Height ~4000

Windows builds of v1.0.21 through v1.0.24 (including all test* pre-releases)
could not complete initial block download (IBD) from an empty data directory.
Nodes would stall during **header presync** around block 4000 with:

    CheckBlockHeader: <hash> high-hash, proof of work failed

### Root Cause

`CompressedHeader` in `src/headerssync.h` (inherited from upstream Bitcoin
Core) only stored 80 bytes of header fields, dropping the RCPU-specific
32-byte `hashRandomX` commitment field. When `GetFullHeader()` reconstructed
the full 112-byte RandomX header for consensus validation, the commitment was
zeroed out, producing an incorrect block hash that failed
`CheckProofOfWorkRandomX`.

Linux nodes and wallets that copied an existing `chainstate` from another
machine were unaffected because they bypassed the header-presync redownload
path. The failure was **not** a consensus fork, a broken mainnet block, or a
RandomX library mismatch.

### Fix

Commit `f7ac48c` adds `hashRandomX` preservation to `CompressedHeader`:
- Store `hashRandomX` during compression
- Restore it in `GetFullHeader()`
- Update `static_assert(sizeof(CompressedHeader) == 80)`

### Test Evidence

- MSYS2 `rcpud.exe` / `rcpu-qt.exe`, empty datadir: synced past 4000 with
  **zero** `high-hash` errors, reached chain tip (6991+)
- User datadir copy (previously stuck at genesis): also passed 4000 cleanly
- Official test* builds (based on `989eae4`, without `f7ac48c`): still stuck
  — expected

## Upgrade Instructions

1. **Remove the old installation** (especially any `test*` build):
   - Windows: `C:\Program Files\RCPU\` (or your custom install dir)
   - Linux: your binary prefix
2. Download the official v1.0.25 installer:
   - Windows: `rcpu-1.0.25-win64-setup.exe`
   - Linux: `rcpu-1.0.25-x86_64-linux-gnu.tgz`
3. Verify SHA-256:
   ```
   2cc8d68c43a21a54bb5efeb8d5f0ff23829c1de404714ddd474513c059b2ebd1  rcpu-1.0.25-win64-setup.exe
   ```
   (see `SHA256SUMS-windows.txt` / `SHA256SUMS.txt` in the release assets)
4. Install and start with an empty (or existing) data directory.

## Note on Previous Workarounds

Copying a `chainstate` from a Linux node that had already synced past 4000
was a temporary workaround for v1.0.21–1.0.24 / test* builds. It is **no
longer needed** with v1.0.25.

## No Consensus Change

This release does **not** alter any consensus parameters, PoW algorithm,
RandomX salt, or network rules. It only fixes a header-compression bug in the
IBD path.

## Version History Note

- `v1.0.24` was an intermediate tag used during CI validation and was never
  promoted to a full release.
- All `v1.0.25-test*` pre-releases (test through test8) are **obsolete** and
  have been marked as pre-release. They lack the `f7ac48c` fix and will fail
  IBD on Windows.
