# RCPU Core v1.4.19 release notes

v1.4.19 fixes how the wallet reports confidential (CT) outputs whose amount it
cannot read right now. Previously such outputs were silently treated as 0, which
could make a balance look too low and hide real funds. They are now surfaced
honestly as "amount unknown" across the RPC and the GUI, and never made
spendable. **No consensus change and no wallet migration.**

## Wallet: CT amount status instead of assuming 0

The wallet now computes a status for every confidential output it owns:

| status | meaning |
|---|---|
| `explicit` | plain non-confidential output, amount is the on-chain value |
| `known` | amount unblinded successfully |
| `known_cached` | amount taken from the wallet's per-output cache |
| `locked` | wallet is encrypted and locked; unblinding needs the keys |
| `no_key` | watch-only wallet; the blinding private key is not present |
| `unreadable` | commitment cannot be unblinded with the available keys |

`locked`, `no_key` and `unreadable` leave the amount unknown. The wallet no
longer reports these as 0: balances, `listunspent` and the transaction history
mark them explicitly instead.

## RPC changes (only new fields, nothing removed or renamed)

- `gettransaction` — each entry under `ct_outputs` gains `amount_status`; the
  top-level result gains `amount_status`.
- `listtransactions` / `listsinceblock` — each row gains `amount_status`,
  `amount_known` and `unreadable` (count of unreadable outputs in the row).
- `listunspent` — each output gains `ct_status` and `amount_known`.
- `getbalances` — gains `ct_unreadable` with `unreadable_outputs`,
  `locked_outputs` and `amount_known`.
- `getwalletinfo` — gains `locked` and `ct_amounts_visible`.
- **New RPC `listunreadableoutputs`** — returns every owned, unspent output
  whose amount is unknown, with `txid`, `vout`, `status`, `confirmations`,
  `address` (when extractable) and `time`. Pass a `filename` to also write the
  same rows as CSV for support exports (absolute path only; existing files are
  not overwritten).

## GUI changes

- **Transaction list** — rows whose amount is unknown show `—` in the amount
  column in amber, with a tooltip explaining why (wallet locked, watch-only, or
  unreadable).
- **Transaction details** — list the unreadable outputs of a transaction
  individually, each with its reason.
- **Coin control** — owned, unspent, unreadable outputs appear in a disabled
  "Unreadable outputs (N)" group. They are listed so the view is not silently
  incomplete, but the group has no checkbox and can never be selected for
  spending.
- **"Needs review" filter** — a new checkbox on the transactions page isolates
  rows with an unknown amount, so they are easy to find and export.
- **Overview page** — when the wallet is locked and amounts are hidden, the
  unlock control reflects that.

## Compatibility

- Consensus: unchanged. No reindex required.
- Wallet: no migration. An output that was reported as 0 before is now reported
  as amount-unknown; unlocking the wallet (or importing the blinding key) makes
  it readable again, at which point it appears in balances normally.
- RPC: existing fields are unchanged; only new fields and one new RPC were
  added.
