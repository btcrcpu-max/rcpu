# RCPU Core v1.4.26 release notes

v1.4.26 is a security and correctness follow-up based on the 2026-11-23
audit. It fixes RPC, wallet, CT fee/amount and release-pipeline issues.
**No consensus rule is changed**, and no reindex is required.

The main compatibility item is F-02: on confidential chains the default
`gettxoutsetinfo` `hash_serialized_3` now commits to CT data
(commitment/nonce/rangeproof), so its value differs from v1.4.25. Monitors,
explorers and UTXO-snapshot tooling must be upgraded together with the node, or
switch to the explicit `hash_serialized_4` hash type.

## Compatibility

- No consensus change. Historical blocks validate exactly as before.
- No reindex required. `hash_serialized_3` is an RPC-side construction; the
  on-disk chainstate format is unchanged.
- **F-02 behaviour change**: CT chains return a CT-aware
  `hash_serialized_3` and a new `ct_aware` field. Old and new nodes at the same
  height will report **different** `hash_serialized_3` values by design.
- `hash_serialized_4` is the explicit CT-aware alias; `muhash` remains the
  legacy (non-CT) construction and returns `ct_aware=false` plus a warning on
  CT chains.
- `key_io_valid.json` test-vector changes are test-only and have no effect on
  node behaviour.

## RPC

- **F-01** `getblockstats` now uses `GetFeeOut()` for v3 transactions. A block
  containing a confidential input no longer produces a negative `txfee` and no
  longer aborts the RPC with `CHECK_NONFATAL`.
- **F-02** `gettxoutsetinfo`:
  - `hash_serialized_3` is CT-aware on confidential chains;
  - new `hash_serialized_4` hash type (explicit CT-aware alias);
  - new `ct_aware` boolean and optional `warning` string, documented in the RPC
    result schema;
  - `hash_serialized_4` should be used by monitoring and explorers that need a
    stable CT-aware UTXO-set commitment.
- **F-05** `listunreadableoutputs` only writes CSV files at or below the
  configured data directory.

## Wallet

- **F-04** confidential outputs whose amount the sender already knows are no
  longer misreported as `no_key` / `unreadable` in `gettransaction`,
  `listtransactions`, `listunspent` and related RPCs.
- **F-06** `GetFeeOut()` only counts fee-shaped outputs (explicit value + empty
  `scriptPubKey`) for v3 transactions. v2 empty-script outputs are ordinary
  (nonstandard) outputs for fee reporting. **Consensus UTXO semantics are
  unchanged.**
- **F-12** legacy and bare-P2PK confidential outputs can be unblinded again:
  the unblind path no longer treats `ExtractDestination()`'s boolean result as
  a failure for P2PK, and legacy wallets use `LegacyScriptPubKeyMan::GetKey`.

## CT / consensus-adjacent

- **F-03** `g_con_elementsmode` is initialised from the selected chain's
  parameters, so `bitcoin-chainstate`/library entry points no longer default to
  CT-off.
- **F-10** `BlindTransaction` checks both `nBanPathAHeight` and
  `nCTStrictRulesHeight`, so legacy nonce Path A is banned at the intended
  height even after the strict-rules height.
- **F-06** was deliberately not extended to a consensus change. A full mainnet
  scan (blocks 0..29600, 44,345 transactions, 36,972 non-v3 transactions) found
  **zero** v2 outputs with an explicit value and empty `scriptPubKey`, so no
  activation height is needed. If such an output ever appears, it must be
  handled with an explicit activation height.

## Build and release

- **F-08** the release workflow pins
  `actions/attest-build-provenance` to the v2 commit SHA
  (`e8998f949152b193b063cb0ec769d69d929409be`).

## Tests

- Full `test_bitcoin.exe` suite: **No errors detected** (691 cases).
- CT suites (`coins_tests`, `coinbase_confidential_tests`, `tx_verify_tests`,
  `confidential_validation_tests`, `blind_tests`, `receive_tests`): 80 cases,
  all pass.
- Functional on `rcpuregtest`: `wallet_confidential.py`,
  `wallet_bumpfee_ct.py`, `wallet_ct_locked_balance.py`, `rpc_blockchain.py`,
  `feature_coinstatsindex.py` all pass; the two RPC suites are now part of CI.
- Non-production mainnet copy: `-reindex` from genesis to height 29600 with no
  CHECK failure; `gettxoutsetinfo` reports `ct_aware=true`,
  `txouts=42904`, `confidential_outputs=8949`.

## Upgrade notes

1. Upgrade all nodes and any UTXO-hash consumer in the same maintenance window.
2. Update monitors/explorers to use `hash_serialized_4` (or accept the new
   `hash_serialized_3`) and check `ct_aware`.
3. During a mixed-version rollout, do not compare `hash_serialized_3` between
   old and new nodes; compare `height`/`txouts`/`total_amount` instead.
4. No reindex is required. Wallet backups are always recommended before any
   upgrade.
