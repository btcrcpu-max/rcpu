# RCPU Core v1.4.24 release notes

v1.4.24 fixes two display problems with confidential amounts that the wallet
cannot unblind. **No consensus change, wallet migration, or RPC change.**

## GUI fixes

### Transaction list and Overview refresh after unlocking

Amounts are cached when the transaction model is built, and the unlock rescan
only marked the status dirty. The result was a transaction list (and Overview)
that kept showing `—` for a confidential output after the wallet was unlocked,
while the details dialog of the same transaction already showed the real
amount — until the wallet was restarted.

Unknown-amount records are now re-decomposed when the wallet reports a
transaction update, and the views are refreshed. Records that already have a
readable amount are skipped, so this adds no cost to normal block processing.

### Details dialog prints unknown amounts as `unknown`, not zero

Credit, debit and net amount were printed from the wallet's stored values,
which are zero for an output the wallet cannot unblind. `0.00000000 RCPU`
reads as "nothing received", which is wrong. These fields now print `unknown`
when the output cannot be valued, using the same per-output status as the
existing "Unreadable outputs" section.

Outputs that are watch-only (no key can ever unblind them) are excluded from
the net-amount check, so a readable spendable net is still shown even when
such an output stays unreadable.

- RPC: unchanged.
- GUI: display only; spending and balance logic are untouched.
