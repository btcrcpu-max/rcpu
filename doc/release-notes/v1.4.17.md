# RCPU Core v1.4.17 release notes

v1.4.17 republishes the v1.4.16 hardening changes with the release pipeline
fixed. It is a drop-in replacement for v1.4.16.

## Why this release exists

v1.4.16 was tagged without a PGP signature and its release page was published
with an empty body. The release tag guard and the GUI signing step had been
downgraded to warnings, so an unsigned tag could still produce a fully signed
set of artifacts.

v1.4.17 restores the fail-closed gates and is published from a **signed tag**:

- unsigned tag, or a tag signed by an unexpected key: release aborts;
- missing `GPG_PRIVATE_KEY` on the GUI path: release aborts;
- `SHA256SUMS.txt` is signed with the RCPU release key and verified before
  publishing.

## Contents (same consensus code as v1.4.16)

- BIP9 thresholds corrected to the 4032-block window: `1815 -> 3629` (90%) and
  `1512 -> 3024` (75%). No active BIP9 deployment, so no immediate effect.
- Non-genesis checkpoints removed; deep-reorg protection now rests on
  `nMinimumChainWork` and `AssumeValid` (anchor height 21,000).
- The checkpoint guard is now **fork-relative**: it rejects a block below the
  last checkpoint only when the active chain already has a different block at
  that height. This keeps IBD working and makes sparse checkpoints safe to
  reintroduce later.

## Upgrade requirement — hard fork at block 29,909

The H-1 dual-algorithm lateness rule activates at height **29,909 on both
mainnet and testnet**. It has been present since v1.4.14.

**Every node, pool and miner must run v1.4.14 or newer before block 29,909.**
v1.4.13 and older will diverge at that height. v1.4.17 is recommended.

## Verification

```
gpg --verify SHA256SUMS.txt.asc SHA256SUMS.txt
sha256sum -c SHA256SUMS.txt --ignore-missing
git verify-tag v1.4.17
```

Windows binaries are published with an explicit `-unsigned` suffix unless a
`WINDOWS_SIGNING_CERT` is configured.

## Compatibility

- No RPC, wallet or consensus change relative to v1.4.16.
- No reindex required when upgrading from any v1.4.x.
