# RCPU Core version v1.0.12

Consensus change: fee-shaped outputs are no longer added to the UTXO set.
This is **not** the same artifact as tag v1.0.11 (`d1d22fb`), which was
docs/hygiene only and does **not** include this fix.

## Consensus (`85325a0`)

- `AddCoin` returns immediately for `CTxOut::IsFee()` (explicit value +
  empty `scriptPubKey`). Those outputs are not inserted into the UTXO set.
- Coinbase transactions that contain a fee-shaped output are rejected with
  `bad-cb-fee-output`.
- Historical mainnet fee-shaped outputs in this repo's scan were all in
  **regular** transactions (zero coinbase hits). A reindex from genesis is
  not expected to fail on `bad-cb-fee-output`.

Empty `scriptPubKey` is anyone-can-spend under the script interpreter.
The outputs remain in block data; only the local UTXO index changes.

## Upgrade

1. Stop `rcpu-qt` / `rcpud`. Confirm RPC port 7337 is closed.
2. Back up `%APPDATA%\RCPU\rcpu\` (blocks, chainstate, wallets) and
   `%APPDATA%\RCPU\rcpu.conf` / `settings.json`. Record `bestblockhash`
   before stopping for a same-chain check after restart.
3. Install the v1.0.12 binaries (user agent must be `/RCPU:1.0.12/`).
   Do not treat a `/RCPU:1.0.11/` binary as this release.
4. Restart **once** without reindex if you need a before/after scan.
   Pre-fix fee outputs stay in chainstate until the index is rebuilt.
5. Restart with `-reindex-chainstate` to drop fee outputs from the UTXO
   set. Block files are kept. Full `-reindex` is unnecessary unless
   block files themselves are suspect.

Windows datadir is `%APPDATA%\RCPU\rcpu\`, not `%APPDATA%\RCPU\` and
not the git checkout.

## Compatibility

- Old nodes keep writing fee-shaped outputs into the UTXO set and can
  spend them. New nodes do not index them. Wallet balances and
  `gettxout` results diverge until the network upgrades and reindexes.
- Treat this as an uncoordinated change in UTXO membership. Operators
  should upgrade and reindex together.
- Light clients that credit empty-script outputs (e.g. interest
  accounting around height 420) can inflate principal by miner fees.
  That is client accounting, not a `chainparams` rule.

## Operator scan

`scripts/scan_fee_utxos.py` (PR #12) walks blocks for fee-shaped vouts
and checks `gettxout`. Exit 3 means unspent fee-shaped coins remain in
**this** node's UTXO set.

Mainnet snapshot on one full node (illustrative, not a supply audit):

| Stage | found | still unspent | exit |
|---|---:|---:|---:|
| v1.0.2, tip 4801 | 1403 | 1403 | 3 |
| same node, pre-shutdown blocks (4803/4805/4807), tip 4807 | 1406 | 1406 | 3 |
| new binary, `--from-height 4808` | 0 | 0 | 0 |
| after `-reindex-chainstate`, tip 4814 | 1409 | 0 | 0 |

`found` counts historical shapes in blocks; it does not go to zero.
`still_unspent` is what reindex clears.

Do not publish per-outpoint JSON from production scans.

## Rollback

Stop the node. Restore `blocks`, `chainstate`, and `wallets` into
`%APPDATA%\RCPU\rcpu\`, and `rcpu.conf` / `settings.json` into
`%APPDATA%\RCPU\`. Start the **pre-fix** binary. A node restored
this way will again report the pre-reindex unspent set.
