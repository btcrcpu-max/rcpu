# RCPU Core v1.0.16 Release Notes

**Consensus soft fork (no reindex required).**

This release tightens two validation rules for confidential transactions:

## B2 — Reject non-CT spend of confidential output

Transactions whose version is **not** `CT_VERSION` (i.e. v2 or earlier) can no
longer spend a previous output whose value is a Pedersen commitment.
Such spends are rejected immediately with
`bad-txns-v2-spend-ct` (`TX_CONSENSUS`).

This closes an edge where a legacy-format transaction could reference a
confidential UTXO and silently treat its amount as zero.

## A2 — Cap confidential rangeproof at 5134 bytes

The maximum size of a `vchRangeproof` is now **5134 bytes**, matching the
internal buffer used by `libsecp256k1-zkp`.  Any output with a proof larger
than this is rejected with `bad-txns-rangeproof-too-large`.
The check is enforced in `CheckTxInputs` before balance verification, and
also defensively in `VerifyRangeProof`.

## Deployment notes

- **No height gate** — the rules activate at the first block validated by a
  v1.0.16 node.
- **No reindex** — existing chain data remains fully valid.
- **Pool node upgraded** at height 4987 with identical `bestblockhash`.
- Scan of 4963 blocks / 4996 v2 non-coinbase txs found **zero** historical
  hits for B2.
- Scan of 1458 v3 txs found **zero** historical hits for A2.

## Included commits

- `a127adb` consensus: reject non-CT spend of confidential output (B2)
- `debf9ee` consensus: cap confidential rangeproof at 5134 bytes (A2)

## Do not do on upgrade

- Do not set `-reindex` or `-reindex-chainstate`.
- Do not change `txindex`, `pruned`, or RPC port settings.
- DNS seed / P2P port `7227` / SCASH branding remain unchanged.
