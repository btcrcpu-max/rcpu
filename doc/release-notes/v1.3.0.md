# RCPU Core v1.3.0 Release Notes

> **Status:** released (tag `v1.3.0`). v1.3.1 is a clean rebuild and v1.3.2
> fixes asset filenames; neither contains consensus changes. This release
> note documents the **Etchash dual-algo** consensus feature.

## Etchash dual-algo (replaces qPoW at height 21,000)

RCPU's dual-algo hard fork activates at **height 21,000** (mainnet/testnet;
150 on regtest): blocks may be mined with RandomX or with the version-bit-30
algorithm. The fork was first shipped in **v1.2.0** with the legacy **qhash
(qPoW)** verifier on bit-30 blocks; **v1.3.0** switches the same bit-30
route to **Etchash** — ECIP-1099-style **light** verification (no full
DAG) — via `fDualAlgoEtchash = true` on mainnet/testnet, with an epoch
length of **6000** blocks (epoch = `(height - 21000) / 6000`; 10 blocks on
regtest).

- Each algorithm runs its own ASERT difficulty instance (600 s target
  spacing per algorithm, anchored at height 20,999 with reference target
  `nBits >> 1`).
- Legacy qhash remains available only when `fDualAlgoEtchash` is false
  (pre-etchash params / test vectors) and is marked deprecated on current
  params.
- `getblocktemplate` for bit-30 templates returns `algo="etchash"` with
  `etchash_epoch`, `etchash_epoch_length`, `etchash_seed_hash`,
  `etchash_cache_size`, `etchash_header_size`, `etchash_hash_field`,
  `etchash_commitment_target`, `etchash_pow_rule` — pools MUST use these and
  MUST NOT recompute epoch/seed from an assumed activation height.

## Consensus-critical notes

- Below height 21,000 the version bit 30 is ignored (RandomX-only rules,
  byte-identical to v1.1.x behavior).
- This is a consensus hard fork; all nodes and pools must upgrade before the
  activation height. See `doc/consensus-params.md` for the parameter table
  and `doc/randomx-mining.md` for pool/gbt integration details.
