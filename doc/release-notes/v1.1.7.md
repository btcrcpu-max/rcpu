# RCPU Core v1.1.7 Release Notes

No consensus change. This is a **wallet / read-block compatibility
upgrade**: since #66 (`64479c8`), the default wallet send path uses
Path C, and new confidential outputs carry a `0x04` nonce prefix that
nodes running versions without #66 cannot deserialize.

## Default send path (since #66)

| Destination | Output |
|---|---|
| `rcpux1...` (confidential address with spend pubkey) | Path C: nonce `0x04 \|\| X`, HKDF-SHA256 rewind nonce |
| Change output | Path C (confidential) |
| Bare `rcpu1...` (no confidential pubkey) | Explicit plaintext amount (unchanged) |
| `-ctlegacy=1` | Entire transaction Path A (`0x02`), behavior unchanged |

## Action required: upgrade all nodes

- Nodes older than **#66 (`64479c8`)** (including v1.1.6 and earlier)
  throw `std::ios_base::failure` in `CConfidentialNonce::Unserialize`
  when they deserialize a block containing a Path C (`0x04`) output.
- This affects **every node** — full nodes and wallet nodes alike — because
  block deserialization (`ReadBlockFromDisk`) is not wallet-only. Once a
  Path C transaction lands on the chain, an unupgraded node that reads
  that block will fail.
- **Please upgrade all nodes (miners, pools, explorers, wallets) to a
  build containing #66 before Path C transactions appear on the chain.**
  Back up wallet data before upgrading wallet nodes.
- This is not a consensus fork: consensus validation is unchanged. The
  `0x04` prefix is a wallet-layer encoding.

## Backwards compatibility

- Historical Path B UTXOs (`0x03`) remain spendable.
  The wallet scans by nonce prefix and dispatches `0x03` to
  `UnblindValueWithKey` and `0x04` to `UnblindValueWithKeyV2`.
- Historical Path A outputs remain spendable without `-ctlegacy=1`.
  The flag only creates new Path A outputs.
- Old blocks remain readable by new nodes (all previous prefixes are
  unchanged); pre-#66 wallets can still send bare `rcpu1` plaintext and
  `-ctlegacy=1` Path A.

## Not in this release

- Viewing keys (`getviewingkey` / `importviewingkey`): opt-in per-output
  `view_seed` export/import, no signing power, not embedded in addresses.
  Follow-up PR `ct/viewkey-rpc` on top of `64479c8`.
- Path A relay ban (mempool / new `0x02` output rejection) and a future
  `nBanPathAHeight` mainnet value: not scheduled.
- Bulletproofs / rangeproof size reduction: not scheduled.
- Checkpoint 10000: not included.
- No new RPC or UI fields were added in #66 (e.g. no plaintext-amount
  warning flag yet).

## Earlier context

- #65 (`70ec5c6`) introduced Path C (`BlindOutputToRecipientV2`,
  HKDF-SHA256 rewind nonce, `view_seed` spec) off by default, plus
  `doc/ct-path-c.md`.
- #66 (`64479c8`) flipped the default send path to Path C and taught
  `CConfidentialNonce` to (de)serialize the `0x04` prefix
  (`PrefixC=4`), with wallet receive-side dispatch by nonce prefix
  (`0x02` / `0x03` / `0x04`).
