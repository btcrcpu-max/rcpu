# RCPU Core v1.4.13 Release Notes

This release contains wallet-usability fixes, a Windows signing work-flow fix,
and the test-suite repairs needed to make `make check` a usable release gate.
It does **not** change consensus or PoW parameters and does **not** change the
27,326 strict-nonce activation height.

## Fixes

- **R-6 mixed-wallet dust change:** the `min_change` decision in
  `CreateTransactionInternal()` now follows whether the change output is
  actually blinded (`change_blinded`), not the wallet-level `change_type`. A
  wallet that holds both explicit and blinded UTXOs and pays a bare `rcpu1`
  address with an explicit-only coin selection no longer keeps a sub-dust
  explicit change that the mempool rejects with `dust`.
- **R-8 wallets without a confidential descriptor:** `DEFAULT_ADDRESS_TYPE` is
  `CONFIDENTIAL`, so a BDB/legacy wallet, an imported-key wallet, or a
  descriptor wallet whose confidential SPK managers were not backfilled yet
  inherited `CONFIDENTIAL` change and failed *before* the change amount was
  known. Such wallets now fall back to plaintext `BECH32` change unless the
  caller explicitly passes `change_type=confidential`, in which case the
  actionable "no confidential descriptor" error is still returned. This makes
  legacy wallets able to send again.
- **R-2 residual:** when a wallet holds non-explicit outputs but has no
  confidential descriptor, the insufficient-funds path now names the missing
  descriptor and points at `doc/wallet-ct-migration.md`.
- **R-7 cleanup:** five mojibake sequences and two column-0 declarations in
  `spend.cpp` were removed.
- **R-4 / L-6 Windows signing:** Authenticode signing moved out of the
  cross-compile `windows-package` job into the `release` publish job, which
  runs no build toolchain. The passphrase reaches `osslsigncode` through a
  `0600` `-readpass` file instead of argv, temporary PFX/passphrase files are
  removed on exit, `SHA256SUMS-windows.txt` is regenerated after signing, and
  the `*-win64-setup.zip` is rebuilt from the signed installer so the ZIP does
  not ship an unsigned EXE.

## Tests and CI

- `make check` is green again: 132 suites, 116 unit-test logs without errors,
  plus `test/util/test_runner.py`. The 24 suites that failed on the v1.4.12
  tree did so because they still asserted Bitcoin mainnet address prefixes,
  WIF keys, the 21M supply cap, 8332/8333 ports, old PoW/subsidy values, and
  Bitcoin regtest assumeutxo constants; those assertions and vectors are now
  derived from this chain.
- `wallet_confidential.py`: new cases 7g (mixed wallet folds a sub-dust explicit
  change into the fee), 7h (blinded input + bare payee keeps a confidential
  change), 7i (legacy wallet reports the missing descriptor, then pays an
  explicit address normally).
- `feature_assumeutxo.py` / `wallet_assumeutxo.py`: pass with the regtest
  assumeutxo constants refreshed for this chain.

## Upgrade notes

- **H-1 (important for old nodes):** `nCTStrictRulesHeight = 27326` contains a
  consensus rule **relaxation** (it permits the historical explicit-zero /
  Path-A form), not a hardening. It activated long ago and no fork has been
  observed, but nodes at **v1.4.4 or older are not compatible** with it and
  must upgrade.
- No consensus, PoW, difficulty or subsidy parameter is changed by this
  release. Wallets that already have a confidential descriptor see no change
  in behaviour.
