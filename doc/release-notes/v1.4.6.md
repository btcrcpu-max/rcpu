# RCPU Core v1.4.6 Release Notes

> **Status:** Release (tag `v1.4.6`).
> This is a security follow-up to v1.4.5. H-1 remains immediate; no consensus
> parameters or activation heights change in this release.

## Security fixes

- **H-1 (ECDSA):** v3 ECDSA `SIGHASH_SINGLE` and
  `SIGHASH_SINGLE|ANYONECANPAY` are now rejected. v1.4.5 only enforced this for
  Taproot/Schnorr signatures. A v3 transaction can spend an explicit
  legacy/segwit-v0 output with ECDSA; `SIGHASH_SINGLE` does not bind the other
  outputs (and the legacy no-output case hashes to one), so this was a remaining
  output-substitution path. The check is in the ECDSA signature checker and
  applies to all v3 ECDSA paths. A P2WPKH regression test covers it.
- **Release authorization:** `workflow_dispatch` is now build-only. Publishing
  requires `github.event_name == 'push'` on a tag, so a manual dispatch cannot
  bypass the signed-tag guard while still publishing artifacts.

## Deployment

- H-1 is **immediate** and independent of `nCTStrictRulesHeight`.
- M-1 (strict confidential nonce) and M-2 (explicit zero) remain scheduled for
  `nCTStrictRulesHeight = 27,326` on mainnet.
- Current observed tip at release time: approximately **25,518**; about
  **1,808 blocks / 6.3 days** remain until M-1/M-2 activation (verify with
  `getblockcount` before deployment).
- Testnet/regtest: 0; other chains: `INT_MAX`.

## Upgrade note

This release is a **consensus tightening**. All nodes that validate v3
transactions should upgrade before relying on H-1 protection for ECDSA spends.
The published v1.4.5 binaries predate this fix.

## Testing

- H-1 ECDSA regression test added and run in CI.
- `build`, `build-gui`, `make-check`, `functional tests`, source/regtest smoke,
  Docker build, release template checks and actionlint are expected to pass.
- Full `transaction_tests` remains at its historical baseline (141 failures,
  same `tx_valid` / `tx_invalid` cases); it is not claimed green.

## Known residual items

- M-5 wallet plaintext metadata is removed from the wallet map, but the wallet
  database is not always rewritten/compacted; old database pages/backups may
  retain deleted values. Rotate pre-upgrade wallet backups and schedule a DB
  rewrite.
- M-3/M-4/M-6-stock/M-9 dedicated PoCs remain follow-up work; their main paths
  are exercised by CI and the release workflow.
