# RCPU Core v1.4.7 Release Notes

> **Status:** Release (tag `v1.4.7`).
> Security follow-up to v1.4.6. H-1 remains immediate; no consensus
> parameters or activation heights change.

## Security and correctness fixes

- **M-2 (zero blinding factor):** `BlindTransaction` now rejects an
  all-explicit input set that would leave a single confidential output with
  blind zero (`C = v*H` amount disclosure). It also rejects zero balancing
  blinds that cancel non-zero input blinds. Wallet change is made
  confidential when a confidential recipient is present; otherwise the
  single-CT case fails closed rather than leaking the amount.
- **M-3 (silent payee reduction):** the wallet no longer injects a dust
  change output by silently reducing the recipient. A confidential input
  paying an explicit recipient without a confidential change now returns a
  clear error. `sendall` follows the same rule.
- **M-4 (Etchash CPU amplification):** `ProcessNewBlock` now performs the
  contextual `nBits` header check before the expensive Etchash
  `POW_VERIFY_FULL` work.
- **M-5 (large confidential outputs):** wallet blinding rejects values at
  or above `2^57` sat before rangeproof construction, matching the consensus
  `max_value <= MAX_MONEY` bound with `min_bits=0`.
- **L-2:** fee outputs are no longer exposed as spendable coins through the
  mempool coin view.
- **L-3:** CT defaults only on RCPU chains; an empty confidential HRP is
  rejected instead of treating any `1...` string as confidential.
- **L-4:** ASERT fields are initialized by default; zero half-life or
  target spacing no longer reaches a division.
- **L-5:** the fee-output standardness exemption applies only to CT v3.
- **L-6:** Etchash epoch division is guarded and `BlindTransaction` rejects
  a blind-vector/input length mismatch.

## Testing

- New M-1 strict nonce test covers null, `0x02` and off-curve nonces at the
  scheduled height.
- New M-2 regression test covers a single confidential output with a zero
  input blind.
- Wallet functional tests cover explicit-only change, confidential change,
  and the M-3 fail-closed paths.
- Build, GUI build, unit checks, functional tests, Docker, source/regtest
  smoke and release template checks are the release gate.

## Deployment

- H-1 is immediate and already deployed in v1.4.6.
- `nCTStrictRulesHeight` remains **27,326** on mainnet. At the observed tip
  of about **25,599**, roughly **1,727 blocks / 6 days** remain.
- M-1/M-2 strict nonce and explicit-zero rules activate at 27,326.
- M-5 wallet plaintext metadata is removed from `mapValue`, but a database
  rewrite/compaction and rotation of pre-upgrade wallet backups remain
  operational follow-ups.

## Compatibility note

M-2 now refuses a previously constructible zero-blind single-CT wallet
transaction. Wallets should provide a confidential change output or a
confidential recipient; this is a privacy hardening change, not a consensus
change.
