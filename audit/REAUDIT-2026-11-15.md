# 2026-11-15 Re-audit and remediation

Current chain height at review: **27,393**. The 27,326 activation is already
past (67 blocks). No chain split was observed.

## H-1 correction

The external audit said "v1.4.9 and earlier cannot accept the explicit-zero
rule". That is incorrect.

Source check:

- `v1.4.5` through `v1.4.9` already contain `allow_zero_explicit` in
  `src/confidential_validation.cpp`.
- All of them also set `nCTStrictRulesHeight = 27326` in
  `src/kernel/chainparams.cpp` and pass
  `nSpendHeight >= nCTStrictRulesHeight` to `VerifyAmounts`.
- The rule is absent in `v1.4.4` and earlier.

Therefore:

- H-1 is **not** a v1.4.10 regression;
- nodes from v1.4.5 through v1.4.10 agree on explicit zero after 27,326;
- only v1.4.4 and older are incompatible.

Do **not** change `nCTStrictRulesHeight` after activation. It also gates the
strict nonce rule, and changing it now can create a new consensus mismatch.
If the explicit-zero relaxation is to be removed, use a separate future-height
soft fork after node upgrades.

## Fixes applied

### H-2: legacy wallet forced into CONFIDENTIAL change

- Do not force `OutputType::CONFIDENTIAL` change when the wallet has no
  confidential scriptPubKeyManager.
- When no confidential change key exists, exclude confidential UTXOs from
  automatic coin selection and reject preselected confidential inputs with an
  actionable error.
- Return an early error for a confidential recipient instead of failing later
  in `ReserveDestination`.

### M-1: restore `min_viable_change`

`SelectionResult::GetChange()` now drops change below
`min_viable_change`, matching upstream, instead of accepting any positive
amount.

### M-4: isolate release signing

The GUI release private key is no longer imported into the AppImage build job
that executes `linuxdeploy`/`appimagetool`. Signing moved to the publish job,
which only downloads the built artifact and never runs third-party binaries.

### L-6: Windows PFX cleanup

Added an `EXIT` trap for `/tmp/rcpu-sign.pfx` so the PKCS#12 file is removed on
failure as well as success.
